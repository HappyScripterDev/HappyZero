# Contributing to Happy Zero

Thank you for your interest in contributing to Happy Zero!

## Code of Conduct

Please be respectful, inclusive, and constructive in all interactions.

## How to Contribute

### Reporting Bugs

- Check existing issues first
- Create detailed bug reports at https://github.com/happyzero/happy-zero/issues
- Include: OS version, steps to reproduce, expected behavior, actual behavior, logs/screenshots

### Suggesting Features

- Open an issue with "Feature Request" label
- Describe use case and proposed solution

### Code Contributions

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature`
3. Make changes following existing code style
4. Test thoroughly
5. Commit with clear messages
6. Submit pull request

## Development Guidelines

### Code Style
- Shell scripts: follow shellcheck recommendations
- Clean, minimal code - no inline comments
- Use existing patterns and conventions

### Testing
- Test build scripts on clean Ubuntu 24.04 environment
- Test ISO in QEMU/KVM before submitting
- Verify no breaking changes to build pipeline

### Commit Messages
Use clear, concise commit messages describing the change.

## Areas for Contribution

- Bug fixes
- Documentation improvements (EN/DE)
- Branding assets
- Package improvements
- Translations
- Welcome app enhancements
- Calamares branding/slides
- Testing on different hardware

## Questions?

Reach out via GitHub issues or discussions.
